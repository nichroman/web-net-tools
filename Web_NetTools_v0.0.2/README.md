# Web_NetTools v0.0.2

Развёртывание двух веб-инструментов на компьютере под управлением Windows так,
чтобы **все пользователи ОС** получали доступ к программам через ярлыки на общем
рабочем столе:

* **WEB_check_nodes v0.0.4** — проверка доступности сетевых узлов (`ping`), порт **3000**;
  исходный проект: `..\WEB_check_nodes_v0.0.4`
* **WEB_check_ports v0.0.1** — сканер TCP-портов, порт **3001**;
  исходный проект: `..\WEB_check_ports_v0.0.1`

Выбран вариант «портативная общая установка»: программы копируются в один общий
каталог, которому выдаются права на изменение для группы «Пользователи», а ярлыки
создаются в общих (машинных) папках Windows.

│   └── node_modules\                     express 4.17.3, cors 2.8.5
├── check-ports\                          WEB_check_ports v0.0.1
│   ├── server.js  index.html  monkey.png
│   ├── hosts.csv  80Port_test_hosts.txt  scan_results*.csv   (наборы и результаты)
│   └── node_modules\
├── launcher\
│   ├── webnettools-common.ps1            общие функции (запуск, проверки, журнал)
│   ├── start-check-nodes.ps1             запуск проверки узлов
│   ├── start-check-ports.ps1             запуск проверки портов
│   ├── stop-webnettools.ps1              остановка обоих серверов
│   ├── webnettools.ico                   иконка ярлыков

Ярлыки, создаваемые установщиком:

| Где | Имя | Что делает |
| --- | --- | --- |
| Общий рабочий стол (`C:\Users\Public\Desktop`) | `Проверка узлов (Web_NetTools)` | запускает узел-1 (порт 3000) и открывает браузер |
| Общий рабочий стол | `Проверка портов (Web_NetTools)` | запускает сканер портов (порт 3001) и открывает браузер |
| Общее меню «Пуск» \ `Web_NetTools` | `Проверка узлов`, `Проверка портов`, `Остановить серверы Web_NetTools` | то же + остановка серверов |

Оба ярлыка на рабочем столе видны всем пользователям и требуют **одну** установку
от администратора. Пользователю права администратора не нужны.

## Установка

1. Убедитесь, что установлен **Node.js 14+** (машинно, для всех пользователей):
   `node -v`. Проверить путь: `C:\Program Files\nodejs\node.exe`.
   Зависимости утилит (`express`, `cors`) уже входят в `packages\check-nodes` и
   `packages\check-ports`, поэтому npm и доступ в интернет при установке не нужны.
2. Запустите **`install.bat`** (двойной щелчок) и подтвердите запрос UAC.
3. Установщик выполнит шаги:
   1. поиск каталогов программ (см. «Откуда берутся программы») и проверка прав;
   2. определение версии Node.js;
   3. остановка ранее запущенных серверов на портах 3000/3001;
   4. `robocopy` в `C:\Tools\WebNetTools` (без `.git` и `.gitignore`);
   5. `icacls` — право «Изменение» группе `S-1-5-32-545` (Пользователи);
   6. подготовка иконки `launcher\webnettools.ico`;
   7. создание ярлыков на общем рабочем столе и в общем меню «Пуск»;
   8. запись `INSTALL.txt` с параметрами установки.
4. Проверьте: ярлыки появились в меню «Пуск» \ Web_NetTools и на рабочем столе,
   после двойного щелчка открывается браузер на `http://localhost:3000` (или `:3001`).

Параметры установки (необязательно):

```
install.bat -InstallDir "D:\Tools\WebNetTools"
install.bat -NodesSource "C:\distr\WEB_check_nodes_v0.0.4" -PortsSource "C:\distr\WEB_check_ports_v0.0.1"
install.bat -SkipAcl            (не менять права доступа)
install.bat -SkipShortcuts      (только скопировать файлы)
install.bat -SkipSearch         (не искать в пользовательских и общих папках)
```

## Откуда берутся программы (поиск исходников)

Установщик определяет каталог программы **по содержимому `server.js`**, поэтому имена
папок могут быть любыми. Порядок поиска:

1. параметр `-NodesSource` / `-PortsSource`;
2. `<проект установщика>\packages` — приложения уже лежат здесь: `packages\check-nodes`
   и `packages\check-ports` (обновляются скриптом `update-packages.ps1`,
   см. `packages\README.txt`);
3. каталог установщика и соседние с ним каталоги — включая **вложенные**, например
   `WEB_check_nodes_v0.0.4\WEB_check_nodes_v0.0.4\server.js` (типовая ситуация после
   распаковки архива, из-за которой возникала ошибка «Не найден server.js»);
4. общие и пользовательские папки: `C:\Users\Public\Desktop`, `C:\Users\Public\Documents`,
   `Desktop`, `Downloads`, `Documents`, `C:\distr`, `C:\Tools` (проверяются только
   каталоги первого уровня, чтобы не подхватить случайную копию программы).
   Если источник найден таким поиском, установщик выводит предупреждение с просьбой
   проверить версию; отключить поиск целиком можно ключом `-SkipSearch`.

Если `server.js` не найден, установщик выводит список всех проверенных мест с их
содержимым и три способа исправления: скопировать каталог в `packages`, задать
`-NodesSource`, положить каталог рядом с установщиком.

Исходники могут лежать в профиле пользователя — на результат установки это не влияет:
программы копируются в общий `C:\Tools\WebNetTools`, получают право «Изменение» для
группы «Пользователи», а ярлыки создаются в общих папках Windows, то есть доступны
всем пользователям. Копирование выполняется режимом `robocopy /COPY:DAT` (без переноса
прав доступа), поэтому ограничения исходной папки на установку не влияют.

Для тиражирования на другие компьютеры удобнее положить каталоги программ в
`packages` — тогда каталог `Web_NetTools_v0.0.2` самодостаточен и его можно запускать
из общей папки (например `C:\distr\Web_NetTools`).


1. Находит `node.exe` (`%ProgramFiles%\nodejs`, `%ProgramFiles(x86)%\nodejs`, `PATH`).
2. Проверяет порт: если сервер уже отвечает на `/api/health` — второй экземпляр не
   создаётся, просто открывается браузер (важно, потому что порт у компьютера один
   для всех пользователей).
3. Если порт свободен — запускает `node.exe ...\server.js` **скрыто** (без окна
   консоли), пишет вывод в `logs\<app>.log` и ждёт готовности сервера до 20 секунд.
4. Если порт занят другим приложением — показывает диалог с объяснением, браузер
   не открывает.
5. Если Node.js не найден или версия старее 13 — показывает диалог со ссылкой на
   https://nodejs.org.

Сообщения выводятся диалоговыми окнами, поэтому видны и при скрытом запуске. Для
автоматического запуска (например, из планировщика задач) у скриптов есть ключ
`-NoDialogs` — тогда сообщения пишутся только в журнал `logs\*.log` и сценарий
не ждёт нажатия кнопки.

Порт и адрес прослушивания ярлык задаёт сам: скрипт подставляет `PORT` (3000 для
проверки узлов, 3001 для портов) и `HOST` (`127.0.0.1`), поэтому глобальные переменные
`PORT`/`HOST` на компьютере ярлыкам не мешают. Другой порт задаётся параметром `-Port`
в сценарии ярлыка, адрес — параметром `-BindAddress` (например `0.0.0.0` для доступа
с других компьютеров). Процесс, запущенный при неудачном старте, автоматически
останавливается, чтобы не остался лишний экземпляр.

Серверы **не** прописаны в автозапуск: они поднимаются по требованию первым
щелчком ярлыка и продолжают работать, пока запущен пользователь, который их открыл
(или пока их не остановят ярлыком «Остановить серверы Web_NetTools»).

## Права доступа и данные

* `icacls C:\Tools\WebNetTools /grant *S-1-5-32-545:(OI)(CI)M /T` — группа
  «Пользователи» (SID `S-1-5-32-545`) получает право «Изменение». Это нужно, потому
  что `check-ports` сохраняет результаты сканирования **в свой каталог**
  (`/api/save-results`, `/api/scan-and-save`), а `check-nodes` читает CSV-списки из
  своего каталога. Без этого права обычный пользователь получил бы ошибку записи.
* Данные **общие** для всех пользователей компьютера: списки узлов и результаты
  сканирования видны всем. Если нужны персональные списки — вынесите каталоги
  `check-nodes`/`check-ports` в `%ProgramData%` с отдельными подкаталогами по
  пользователю (требуется правка `server.js`: сейчас каталог данных = `__dirname`).
* Плата за простоту: код программ тоже доступен на изменение обычным пользователям.
  Если это неприемлемо — используйте вариант «Program Files (только чтение) +
  `C:\ProgramData\WebNetTools\data`» с правкой `server.js` в обоих проектах.

## Порты, сеть, брандмауэр

* Порт 3000 — проверка узлов, порт 3001 — проверка портов; порт у компьютера общий,
  поэтому одновременно работает только один экземпляр каждой программы.
* Оба сервера слушают **только `127.0.0.1`** (`HOST` по умолчанию), страница
  доступна с этого же компьютера и запрос брандмауэра Windows не появляется.
* Для доступа с других компьютеров: запустите сервер с `set HOST=0.0.0.0` (или
  добавьте `HOST=0.0.0.0` в параметры запуска) и создайте разрешающее правило,
  например: `netsh advfirewall firewall add rule name="Web_NetTools 3000-3001" dir=in action=allow protocol=TCP localport=3000,3001`
* Переопределение порта: `set PORT=3002` перед запуском `node server.js`
  (ярлыки используют значения по умолчанию; при смене порта поправьте аргумент
  `-Port` в соответствующем скрипте `launcher\start-*.ps1`).

## Обновление версий

1. Остановите серверы ярлыком «Остановить серверы Web_NetTools».
2. Скопируйте исходные проекты новой версии в `..\WEB_check_nodes_*` / `..\WEB_check_ports_*`
   (или укажите пути через `-NodesSource` / `-PortsSource`).
3. Обновите приложения в дистрибутиве:
   `powershell -NoProfile -ExecutionPolicy Bypass -File update-packages.ps1 -Force`
   (при необходимости сначала выполните `npm install` в каталоге-источнике).
4. Запустите `install.bat` — файлы перезапишутся, ярлыки пересоздадутся.
5. Пользовательские CSV-наборы сохраняются, но перед обновлением лучше сделать копию.

## Удаление

`uninstall.bat` (права администратора) — останавливает серверы, удаляет ярлыки с
общего рабочего стола и из общего меню «Пуск», затем удаляет каталог установки.
Без подтверждения: `uninstall.bat -Force`.

## Windows 7 x86

* Нужен **Node.js 14.21.3 x86** (`node-v14.21.3-x86.msi`) — последняя ветка,
  поддерживающая Windows 7; он устанавливается в `C:\Program Files (x86)\nodejs`
  и определяется лаунчером автоматически.
* Для проверки узлов используйте сборку `WEB_check_nodes_v0.0.4_win7x86`
  (express 4.18.2), передав её путь: `install.bat -NodesSource "..\WEB_check_nodes_v0.0.4_win7x86"`.
* Ярлыки запускаются через Windows PowerShell 2.0 — в скриптах используются только
  совместимые конструкции (`System.Net.Sockets.TcpClient`, `New-Object -ComObject
  WScript.Shell`, никаких `Get-NetTCPConnection`, `Test-NetConnection`, `ConvertTo-Json`).
* Если политика запрещает `.ps1`, переключите ярлыки на резервные VBScript-скрипты:
  цель ярлыка — `wscript.exe "C:\Tools\WebNetTools\launcher\fallback\start-check-nodes.vbs"`
  (аналогично для портов). Установщик делает это автоматически, если PowerShell не найден.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Ярлык открывает браузер, но страница не загружается | `logs\check-nodes.log`, права на каталог, `node -v` |
| «Порт 3000 занят другим приложением» | `netstat -ano \| findstr :3000`, закрыть чужое приложение или задать `PORT` |
| Диалог «Node.js не найден» | установить Node.js 14+, проверить `C:\Program Files\nodejs\node.exe` |
| «Не удалось сохранить файл» в сканере портов | права «Изменение» на `C:\Tools\WebNetTools\check-ports` (повторить `install.bat`) |
| Пользователь не видит ярлыки | ярлыки лежат в `C:\Users\Public\Desktop`; проверить `install.bat -SkipShortcuts` и права на файл `.lnk` |
| Повторный щелчок ярлыка не создаёт второй процесс | так и задумано: сервер один на компьютер, открывается только браузер |
| «Не найден server.js в каталоге …» | скопируйте каталоги программ в `packages\check-nodes` и `packages\check-ports` либо запустите `install.bat -NodesSource "…" -PortsSource "…"` (установщик выводит список проверенных мест с их содержимым) |
| «Сервер … не ответил за 20 секунд на порту 3000» | проверьте `logs\check-nodes.log` и занятость порта (`netstat -ano \| findstr :3000`) — ярлык сам задаёт порт, глобальные `PORT`/`HOST` ему не мешают |
| Серверы запущены на нестандартных портах | остановка: `stop-webnettools.ps1 -Ports 3020,3021 -AppRoot "C:\Tools\WebNetTools"` |

Проверка вручную:

```powershell
Get-Process node | Select-Object Id, Path
Invoke-WebRequest http://127.0.0.1:3000/api/health | Select-Object -ExpandProperty Content
Invoke-WebRequest http://127.0.0.1:3001/api/health | Select-Object -ExpandProperty Content
```

Остановка без ярлыка: `Get-Process node | Where-Object { $_.Path -like '*WebNetTools*' } | Stop-Process -Force`
(для процессов других пользователей нужны права администратора).

## Изменения в проектах приложений (v0.0.4 / v0.0.1)

Чтобы лаунчер мог надёжно определять состояние сервера, в `server.js` обоих
проектов добавлено минимальное:

1. `WEB_check_nodes_v0.0.4`: `PORT` читается из переменной окружения (по умолчанию 3000),
   добавлен `HOST` (по умолчанию `127.0.0.1`), добавлен эндпоинт `GET /api/health`,
   добавлена обработка `EADDRINUSE`.
2. `WEB_check_ports_v0.0.1`: добавлен `HOST` (по умолчанию `127.0.0.1`), в
   `/api/health` добавлены поля `host` и `port`, сервер слушает `HOST`.

Функциональность интерфейса и формат CSV-результатов не изменились.
