# check-nodes (WEB_check_nodes v0.0.4)

Веб-версия проверки доступности сетевых узлов: Node.js-бэкенд (`server.js`, Express)
выполняет системный `ping`, страница `index.html` (ES5, совместима с IE11) показывает
состояние сервера, статистику, результаты и экспорт в CSV. Повторяет функциональность
PowerShell-скриптов `CheckNodes\win10x64\check_nodes.ps1` и
`CheckNodes\win7\check_pns2_nodes.ps1`, но работает через браузер.

## Возможности

- Список узлов берётся из CSV-файлов каталога проекта (выпадающий список
  «Выбор набора данных»); поддерживаются CSV (разделитель `;`, колонки `Address;Comment`)
  и TXT (один адрес на строку), а также ручной выбор файла кнопкой «Выбрать файл».
- Количество ping-запросов на узел: 1-100 (по умолчанию 10).
- Таймаут одного запроса: 100-5000 мс (по умолчанию 1000 мс, параметр API `timeout`).
- Статусы: «Доступен» (потерь нет), «Частично доступен» (потери менее 50 %), «Недоступен».
- Индикатор состояния сервера, прогресс-бар, статистика по статусам, таблица
  результатов, экспорт CSV на стороне браузера.

## Запуск

```
npm install
npm start
```

или `npm_start.bat` (открывает браузер на http://localhost:3000).

## Параметры окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | 3000 | порт веб-сервера |
| `HOST` | 127.0.0.1 | интерфейс прослушивания; `0.0.0.0` — доступ с других ПК (потребуется правило брандмауэра) |

Пример: `set PORT=3010 && set HOST=0.0.0.0 && npm start`

## API

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | `/api/health` | состояние сервера (приложение, версия, Node.js, `host`, `port`) |
| GET | `/api/datasets` | список CSV-файлов каталога проекта |
| GET | `/api/dataset/:filename` | содержимое выбранного CSV-файла |
| GET | `/api/ping?host=&count=&timeout=` | проверка одного узла |

## Состав

- `server.js` — Express-сервер (ping через `child_process.exec`, API, обработка `EADDRINUSE`).
- `index.html` — интерфейс (ES5/XMLHttpRequest, совместим с IE11).
- `nodes.csv`, `pns2_nodes.csv`, `pns2.1_nodes.csv` — примеры списков узлов.
- `monkey.png`, `monkey.ico` — логотип и иконка ярлыков.
- `npm_start.bat` — локальный запуск из каталога проекта (в git не попадает).

## Особенности реализации

- Проверка узлов выполняется системной командой `ping` (`child_process.exec`).
  Windows пишет вывод ping **в кодировке консоли** (в русской Windows это CP866),
  а Node.js читает поток как UTF-8, поэтому `server.js` получает поток как буфер и
  декодирует его подходящей кодировкой (UTF-8 / CP866 / CP1251 / CP437 — выбирается
  вариант с наибольшим числом распознанных ответов). Дополнительно ответ
  распознаётся по признаку `TTL=`, который не зависит от языка и кодировки:
  без этого все узлы получали статус «Недоступен».
- `PORT` и `HOST` читаются из переменных окружения (см. выше), сервер слушает
  только локальный интерфейс.
- Время ответа вычисляется только по распознанным строкам ответов; если время
  определить не удалось (необычная локаль), интерфейс показывает `N/A`,
  но статус доступности остаётся верным.

## Развёртывание для всех пользователей Windows

Общая установка с ярлыками на общем рабочем столе выполняется отдельным проектом
`..\Web_NetTools_v0.0.2` (запуск `install.bat` от администратора):

- программы копируются в `C:\Tools\WebNetTools` (`check-nodes`, `check-ports`, `launcher`, `logs`);
- каталог получает права «Изменение» для группы «Пользователи», поэтому запись
  результатов сканирования работает без прав администратора;
- на общем рабочем столе и в общем меню «Пуск» создаются ярлыки, которые запускают
  сервер скрыто (без окна консоли) и открывают браузер;
- серверы слушают `127.0.0.1`, поэтому запрос брандмауэра Windows не появляется;
- один экземпляр программы на компьютер: повторный щелчок ярлыка только открывает браузер.

Для Windows 7 x86 используется сборка `..\WEB_check_nodes_v0.0.4_win7x86`
(Node.js 14.21.3 x86) — путь передаётся установщику параметром `-NodesSource`.
Подробности — в `Web_NetTools_v0.0.2\README.md`.
